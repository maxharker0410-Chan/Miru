# Windows Companion V1 基準檢查表

這份文件用來記錄「未修改的 Miru」在 Windows 上是否能正常運作。完成
基準測試以前，不應把角色渲染的大型改動合併到 `main`。

## A. 測試環境

- [ ] Windows 版本與更新編號已記錄。
- [ ] CPU、GPU 與 RAM 已記錄。
- [ ] Python 版本已記錄。
- [ ] Node.js 與 npm 版本已記錄。
- [ ] Rust、Cargo 與 Tauri CLI 版本已記錄。
- [ ] Microsoft Edge WebView2 Runtime 版本已記錄。
- [ ] Live2D SDK 與模型來源、版本、授權已記錄。

建議將結果寫在本機測試紀錄，不要提交帳號、API Key 或私人路徑。

## B. 安裝與啟動

- [ ] 依 `docs/BUILDING.md` 安裝依賴。
- [ ] `.env` 由 `.env.example` 建立，且未加入 Git。
- [ ] 原始 Miru 可以啟動。
- [ ] 桌寵視窗可顯示。
- [ ] 關閉後可正常重新啟動。
- [ ] 工作管理員中沒有殘留重複程序。
- [ ] 啟動失敗時有可閱讀的錯誤訊息。

## C. 桌寵基準

- [ ] 透明背景正常。
- [ ] 角色不會被裁切或變形。
- [ ] 拖曳視窗正常。
- [ ] 點擊穿透與可互動區域正常。
- [ ] 縮放與位置調整正常。
- [ ] 關閉、隱藏與喚回快捷鍵正常。
- [ ] 多螢幕與不同 DPI 下位置合理。
- [ ] 睡眠／喚醒或鎖定／解鎖後仍可使用。

## D. 對話與模型設定

- [ ] 未設定模型時，畫面明確提示如何設定。
- [ ] 設定模型後，文字訊息可送出並收到回答。
- [ ] Thinking 狀態不會永久卡住。
- [ ] 網路或 API 錯誤不會讓桌寵崩潰。
- [ ] API Key 不會出現在畫面、日誌或 Git 變更中。
- [ ] 能分辨 API 模型與本機模型，不把 ChatGPT Plus 當作 API 額度。

## E. 記憶與主動陪伴

- [ ] 對話記憶能新增與重新讀取。
- [ ] 記憶能查看、修改與刪除。
- [ ] Journal 可建立且不包含不必要的敏感內容。
- [ ] Attention Engine 可以完全暫停。
- [ ] 安靜時段生效。
- [ ] 主動訊息不會連續轟炸使用者。

## F. 隱私控制

- [ ] 螢幕觀察預設關閉。
- [ ] 麥克風預設關閉。
- [ ] 每項感知功能都有清楚的開關與狀態。
- [ ] 關閉後不再背景擷取。
- [ ] 使用者可以清除對話與記憶。
- [ ] 日誌不記錄密碼、API Key 或完整敏感畫面。

## G. 自動測試

執行專案現有測試，至少記錄：

```powershell
python -m pytest -q
```

如果完整測試需要外部服務，先執行與 Windows、桌寵、角色及安全相關的
測試，並將跳過原因記錄清楚。不得為了讓測試變綠而提交真實憑證。

## I. 進入角色改造的門檻

只有下列條件成立，才開始拆分目前 `templates/pet.html` 的 Live2D 程式：

- 原始桌寵在 Windows 上可啟動並可正常關閉。
- 已知道 Live2D 缺少哪些本機元件與授權限制。
- 已保存至少一份可回復的基準紀錄。
- 現有 Windows／桌寵測試沒有未知的基礎失敗。
- Character Adapter 規格已確認。

若某項失敗，先把失敗記錄成 issue 或 PR checklist；不要把基礎問題和
角色改造混在同一個 commit。
