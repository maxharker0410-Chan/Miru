# S. Chat 魔法異世界整包匯入

在「整包匯入」一次選擇 `S.Chat_魔法異世界_世界資料包_V1.0.zip` 與 `GAME_WebP_SChat.zip`，按「一次匯入」。沿用目前的登入與聊天模型，不需要新的 API Key。兩包合計上限 512 MiB；圖片包包含 54 名重要角色、99 名 NPC、42 張背景，合計 195 張 WebP。

## 匯入與角色管理

- 先核對 ZIP 路徑、版本、角色 ID、綁定、195 張圖片的大小、SHA-256、尺寸與解碼，再保存故事；不執行包內 Python、Markdown 或其他文件中的指令。
- 使用原 char_、npc_、loc_ ID。12 張不透明人物圖保留原背景與原 WebP，不去背、不裁切、不拉伸；星輝圖書館直接綁定 `loc_02_library`。
- 相同包重匯使用既有故事與遊玩紀錄，不重置記憶、同行或圖片。不同版本拒絕覆蓋，ID 刪除／合併／拆分需另設遷移。
- 名冊、角色編輯與場景編輯每頁六筆，支援姓名、職位、圖片索引、ID 搜尋，以及角色類型與地區篩選。只載入本頁預覽與目前場景／在場人物，不在啟動時解碼全部 195 張。
- 保留世界包的 53 個地點與圖片包新增的 24 個區域 ID，共 77 個可選地點。圖片區域和地點保持不同 ID；已有區域描述的子地點可共用區域背景。沒有對應圖的自然地點保留文字，不用其他城市的圖片假冒。

## 遊玩、同行與續玩

開始故事後，從「角色名冊」搜尋角色。「確認已抵達」保存該角色在目前位置；「邀請同行」加入本局隊伍；「結束同行」將其留在原地；「離開現場」移出當下畫面。作者明定不可同行的角色會拒絕加入。未設定跟隨資格不被解讀成永遠禁止。

在對話中描述明確前往或已抵達的行動，導演回傳 `travel_status=arrived` 後，同一回合先更新場景、背景和同行者位置，再讓角色在目的地回覆。不必再按一次目的地。詢問路線、想去或未出發的計畫仍保存旅行提案；手動目的地是備用入口。重選目前地點保留對話、在場角色和狀態。未設定交通時間不推算成零秒；沒有啟用離線時間推進或自主排程。

重要角色通常在原設定區域工作和生活。只有已有同行，或公開劇情確實記錄的冒險／任務移動，才會在其他區域出現。角色自行移動需原在場者或已知旅程、有效目的地、冒險／任務原因及逐字公開依據；出發和抵達分開保存，不臨時編造遠方人物的任務讓其登場。未發言者不因此離隊；明確留在原地、私人會面或離隊則重算現場。

角色被提到不表示到場；遠處角色不能被導演直接搬到現場。每名角色保持自己的記憶；模型只收到相關現場、授權事實、自身關係與自己的記憶，不整包收到世界作者資料、153 人的設定、圖片或其他角色秘密。重要角色的公開人物名錄不代表私人交情。NPC 不自動取得重要角色專屬知識授權。

每局保存世界版本、run_id、位置、角色狀態、隊伍、獨立記憶、旅行提案及事件 ID／revision。重送同一回合不再生成或提交；過期 revision 拒絕覆蓋；模型失敗不保存半個回合。另開遊玩紀錄不繼承前一局玩家造成的變化。重新開啟故事會讀取最近的存檔。

## 素材文字的邊界

本 V1 世界包只包含完整地區一的具名索引，其餘許多人物為 `name=null`、`role_placeholder`。匯入會沿用作者職位稱呼，圖片上的姓名保留為可搜尋的素材標籤，不擅自當作完整人物卡。NPC 的職位取自圖片索引，沒有補造人格、排程或私密關係。後續可補充明確角色卡；共通設定、傳說、待定提案與事件種子不被自動改寫為已發生事實。

## 更新作者設定書

匯入世界後可按「更新設定書」，選擇包含七区完整角色卡和 NPC 表格的 `.docx`（上限 16 MiB）。依區域及文件角色編號核對原 54 個重要角色與 99 個 NPC ID，更新姓名、個性、能力、自身關係、區域布局與工作資料。圖片索引名稱只作搜尋別名，作者新設定的姓名才是角色名稱。

更新前保留原設定備份，僅原子更新故事定義，不覆寫任何 session、圖片或聊天模型憑證。重複上傳相同內容不新增版本或備份；過期設定版本、缺漏或重複角色及不安全文件會拒絕，既有進度保留。遊玩紀錄只在讀回時更新作者設定版本標記，角色 ID、位置、已同行關係、記憶及事件 revision 保留。

完整區域原文保存在作者資料；模型只取得公開世界規則、相關區域公開布局及該角色自己的卡，其他人的私密關係和角色卡不送進角色請求。圖片生成關鍵字保留在作者卡中，但不作角色對話指令。新開局沿用原模型選擇原生、轉生、穿越或自訂身世；既有旅程續玩，不反覆重建身分。新書中仍待實作的完整自主排程、離線時間及關係數值系統保持待定，不因匯入文字自動啟用。

## 測試與發布範圍

單元測試使用合成公開資料，不包含使用者 ZIP、故事、API Key 或登入憑證。開發驗收使用完整的兩份實際 ZIP，分別測試 Windows 打包程式及限制 API 範圍的手機預覽。手機預覽採私人配對，正式 Vercel／Supabase 部署不因本 PR 更新。

測試指令：

```text
python -m pytest -q
node --test tests/schat_library_checks.cjs tests/schat_speech_checks.cjs
node --check assets/js/schat.js
node --check assets/js/schat-library.js
```

Windows 使用原 `build_windows.ps1 -SkipInstaller`；PyInstaller 包含 `world_import`、`world_runtime`、`story_tracker` 與 WebP 支援。依原帳號服務計算聊天費用，匯入本身不呼叫模型。
